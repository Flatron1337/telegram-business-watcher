   - В текстах `/start`, `/help` и в меню команд бота НЕ ДОЛЖНО быть ни одного упоминания `/reactor`.
   - Если любой пользователь с `user.id != settings.reactor_owner_id` (даже если он есть в `ALLOWED_USER_IDS`) напишет `/reactor` или нажмёт callback `reactor:*`, бот НЕ ДОЛЖЕН отвечать «⛔️ Доступ ограничен» — он обязан полностью проигнорировать событие без единого сообщения в ответ, чтобы не выдать существование секретной команды.
2. **По умолчанию ВЫКЛЮЧЕН:**
   - При первом запуске или отсутствии записи в БД/Redis реактор обязан быть выключен (`enabled = False`).

### Задачи Фазы 2:

1. **Критическое исправление ZWJ-эмодзи «Огненное сердце» (`"❤️\u200d🔥"`):**
   - В Фазе 1 в `database/models.py`, `database/connection.py` и `handlers/reactor.py` была записана строка `"❤️🔥"` (два отдельных эмодзи без Zero-Width Joiner `\u200d`), которая вызывает в Telegram API ошибку `400 REACTION_INVALID`.
   - Замени везде `"❤️🔥"` на валидный единый ZWJ-эмодзи `"❤️\u200d🔥"` (`"❤️🔥"`).
   - В `ReactorConfig.from_dict()` добавь авто-нормализацию: если из БД или Redis пришла старая строка `"❤️🔥"`, автоматически заменяй её на `"❤️\u200d🔥"`.

2. **Создание движка авто-реакций (`services/reactor_service.py`) и интеграция:**
   - Создай `services/reactor_service.py`:
     - Чистая функция `should_react_to_message(config: ReactorConfig, conn_user_id: int, owner_id: int, chat_id: int, sender_id: int | None) -> bool`:
       - Возвращает `False`, если `not config.enabled` или `conn_user_id != owner_id` (строгая изоляция: реактор работает ТОЛЬКО для бизнес-подключения самого `reactor_owner_id`, никогда не срабатывая на подключениях других людей из `ALLOWED_USER_IDS`!).
       - Если `config.target_chat_ids` не пуст и `chat_id not in config.target_chat_ids` — возвращает `False`.
       - Если `config.only_incoming` равен `True` и `sender_id == owner_id` (исходящее сообщение самого владельца) — возвращает `False`.
       - Иначе возвращает `True`.
     - Асинхронная функция `apply_auto_reaction(bot: Bot, message: Message, repository: BusinessRepository, settings: Settings, conn_user_id: int) -> bool`:
       - Загружает `config = await repository.get_reactor_config(settings.reactor_owner_id)`.
       - Проверяет `should_react_to_message(...)`.
       - Если `True` — вызывает через `safe_telegram_call` метод `bot.set_message_reaction(chat_id=message.chat.id, message_id=message.message_id, reaction=[ReactionTypeEmoji(emoji=config.emoji)], is_big=config.is_big)`. Любые ошибки Telegram API логируются на уровне `debug`/`warning` и перехватываются, чтобы ни при каких условиях не прервать сохранение сообщения в `on_business_message`.

   - В `DummyBot` (в `tests/`) добавь метод `set_message_reaction(self, chat_id: int, message_id: int, reaction: list[Any], is_big: bool = False, **kwargs: Any) -> bool`, который записывает вызовы в `self.reactions: list[dict[str, Any]]` для честных проверок в тестах.
